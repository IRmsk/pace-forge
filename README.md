# pace-forge

**运动轨迹合成引擎** — 把一条几何折线变成一份经得起统计检验的跑步数据。

纯 Rust，单二进制，CLI + Web 双模式，零可选依赖。

---

## 这是什么

任何一份"跑步记录"都不是孤立的数字，它是一组**互相约束**的物理量：

```
距离 ←→ 时长 ←→ 配速
配速 ←→ 步频 ←→ 步幅
步频 ←→ 步数 ←→ 每 10 秒分布
```

你改任何一个，其他几个必须跟着动，否则数据自相矛盾。常见做法是各算各的，再拼在一起——这样出来的数据，随便一除就露馅。

pace-forge 的做法是：**只造一个自由变量（速度），其余全部由它派生**。

```
轨迹几何 → 弧长 / 曲率
        → OU 速度剖面（含起跑热身、终点冲刺、弯道预判刹车）
        → 每点速度 + 疲劳度 → 步态 (cadence, stride)
        → dt = d / v  → 时间戳
        → 步频 × dt/60 → 步数 → 10 秒分桶
```

三个量从同一个源头长出来，**结构上不可能对不上**。

## 核心能力

### 生物力学步态模型

步频不是常数，也不是随机数。它和速度之间有一条稳定的经验关系：

```
步频(步/分) ≈ 34.4 + 44.5 × 速度(m/s)
```

这条式子来自真实跑步记录的线性回归，误差 ≤2 步/分：

| 配速 | 实测步频 | 公式 |
|------|---------|------|
| 5:31/km | 170 | 169 |
| 6:40/km | 144 | 146 |
| 7:02/km | 139 | 140 |
| 8:19/km | 125 | 124 |

常见的拍脑袋公式 `150 + 12v` 在 6:40/km 会给出 180，比实测高 36 步，而且形态反了——真实数据是**步幅主导**，慢配速时步频掉得更快。

硬约束写进类型里，误差 < 1e-9：

```
v = (cadence / 60) × stride
```

### 不是白噪声

10 秒粒度的数据如果靠均匀随机数抖动，相邻桶互相独立，一阶自相关接近 0。真人的步频有惯性。

用 Ornstein-Uhlenbeck 过程做均值回归：

```
c_{t+1} = c_t + θ(target_t − c_t)·Δt + σ·√Δt·Z,   Z ~ N(0,1)
```

实测对比：

| 方案 | 标准差 | 相邻差 | 一阶自相关 |
|---|---:|---:|---:|
| 均匀随机 | 3.36 | 3.66 | **0.089** |
| OU 均值回归 | 2.01 | 1.42 | **0.569 ~ 0.71** |

θ=0.07 对应相关时间约 14 秒——桶间隔 10 秒时相关性还有 0.5，不会退化成白噪声。

### 速度剖面是物理的

- **起跑热身**：前 20 秒从 0.85× 匀速 ramp 到 1.0×
- **中段起伏**：OU 均值回归
- **弯道预判**：`v² ≤ v_corner² + 2·b·d`，提前 40m 以 1.5 m/s² 收速
- **终点冲刺**：最后 150m 线性提速 12%

全程匀速跑完是最容易识别的机器特征之一。

> 关于弯道减速：400m 标准跑道内圈半径 36.8m，2.8 m/s 配速过弯的向心加速度只有 0.198 m/s²，远低于人体上限（约 2.5 m/s²）——**这个配速本来就不需要减速**。弯道限速只在速度 >4 m/s 或半径 <10m 的急弯实际生效。

### 时间戳精确对齐

`dt_i = d_i / v_i`，速度快的段用时短。总时长用**最大余数法**分配，`Σdt` 从构造上精确等于目标，不存在累积舍入误差。

实测三者偏差：

```
剖面速度 vs 实测速度：平均 0.23%，最大 0.49%
分桶速度 vs 桶内实测：最大 0.00%
总时长误差：0 ms
```

## 两种路线模式

### 自由路线

在中心点周围生成闭环折线，自动凑到目标里程，支持必经打卡点。

### 操场绕圈

按 World Athletics 标准 400m 跑道建模：

```
        ┌──────────────────────┐
       ╱                        ╲
      │   直道 84.39m            │     弯道半径 36.50m
       ╲                        ╱      半圆长 115.61m
        └──────────────────────┘

  一圈 = 84.39×2 + 115.61×2 = 400.00m
```

支持 1–8 道（每道宽 1.22m）。实测：

| 道次 | 圈长 | 生成 5 圈 | 闭合误差 | 弯道曲率 |
|---|---:|---:|---:|---:|
| 第 1 道 | 400.0m | 1999.1m | 0.00m | 0.02719 |
| 第 2 道 | 407.7m | 2037.5m | 0.00m | 0.02632 |
| 第 4 道 | 423.0m | 2114.2m | 0.00m | — |

理论曲率 `1/36.8 = 0.02717`，实测 0.02719。直道曲率 0.00000。

## 提交前自检

**宁可本地失败，也不要把注定被驳回的报文发出去。** 驳回会记错误次数，异常多了触发风控。

七大类，分三级：

| 检查项 | 等级 | 内容 |
|---|---|---|
| 时间轴 | 致命 | 起止戳缺失、顺序颠倒、跨度与 `totalTime` 不符 |
| 轨迹时间 | 致命 | 首末点未落在报文边界、时间戳非严格递增 |
| 里程 | 致命 | 折线实测与声明差 >2m |
| 坐标 | 致命 | 越界 / (0,0) / 相邻跳变 >200m |
| 打卡点 | 致命 | 任一必过点最近距离 >0.5m |
| 分桶 | 致命 | 桶数不符、步数和不等于总步数 |
| 物理 | 致命/警告 | 配速超规则区间、步频超人体范围、步幅异常、步态不匹配 |


### 作为库

```rust
use pace_forge::track::{plan, retime, simulate, inspect, Check, PlanRequest, SimParams};

// ① 规划
let track = plan(&req, &mut rng)?;

// ② 由速度反推时间戳
let (times, _, len) = retime(&xy, 720, start_ms, seed, &KinParams::default(), 1.0, 8.0);

// ③ 合成步数
let sim = simulate(&timed, &SimParams {
    total_distance_m: len as f64,
    total_sec: 720,
    start_ms,
    target_steps: None,   // None 由模型推算
    seed,
    ..Default::default()
})?;

// ④ 自检
let report = inspect(&check);
if report.blocked() {
    eprintln!("{}", report.summary());
}
```

## 设计取舍

**为什么速度是唯一的自由变量？**
因为它是唯一一个"人不会精确控制但会自然变化"的量。距离和时长是目标，步频和步幅是结果。反过来做就会得到互相矛盾的数据。

**为什么用 OU 而不是 AR(1) 或滑动平均？**
OU 是连续时间的均值回归过程，参数有物理含义（θ 是回归速率，σ 是波动率），相关时间 `1/θ` 可以直接换算成秒。AR(1) 是它的离散特例，滑动平均则没有平稳解。

**为什么不引 `rand_distr`？**
只需要一个标准正态。Box-Muller 十行就够，省一个依赖树。

**为什么自检这么严？**
一次驳回的代价不是"这次失败"，而是错误计数 +1。这个计数会累积到下一次正常提交上。
