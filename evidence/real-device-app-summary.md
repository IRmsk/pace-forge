## 由样本 A/B 能定的结论

### 1. `speed` 是配速（min/km），不是 km/h

明细里的 `speed` 若为 km/h，`最快配速` 会与平均值反序（km/h 越大越快，但数值上
「最快」应大于平均）。实测两条记录都是 **最快 < 平均**（2'13" < 6'44"），
说明字段语义是配速，且「最快配速」取的是 `min(speed)`。
→ 与 [`api/submit.rs`](../api/submit.rs) 里 `speed = 1000/(60v)` 的口径一致。

### 2. 配速图会被极端点撑爆纵轴，不能用来读分布

两条记录的配速图最深处分别是 **172'00"** 和 **364'00"**，而平均只有 6'44" / 6'08"。
曲线「贴着顶部」不是因为它恒定在 0 附近，而是因为纵轴被极端值拉到 172/364，
6'44" 在那根轴上只占 4%。

换算：172 min/km → v = 0.097 m/s（5 秒走 48cm）；364 min/km → v = 0.046 m/s（5 秒走 23cm）。
即**真机确实会产生「几乎静止」的采样点**，且深度可达 364 min/km。

### 3. 步频/步幅是「距离 ÷ 步数」派生的，不是独立传感器量

- A：2670m ÷ 1623 步 = 1.645 m/步 ✓（显示 164cm）；1623 ÷ 17.97min = 90.3 ✓（显示 90）
- B：3150m ÷ 2003 步 = 1.573 m/步 ✓（显示 158cm）；2003 ÷ 19.33min = 103.6 ✓（显示 104）

两个字段都能由 `总里程 / 总步数 / 总时长` 精确复算，说明 App 是按这一步派生的。
**手机计步器少计是常态**（本样本 90 步/分对 6'44" 配速而言显著低于人体实际步频
140 步/分上下），所以「步频 90 + 步幅 1.64m」反映的是**计步口径**，不是真实步态。

## 与当前实现（`d2e3135`+）的实测差异

| 指标 | 真机 A | 真机 B | 当前实现（2km/720s） |
|---|---|---|---|
| 平均配速 | 6'44" | 6'08" | 5'47" |
| 最快配速 | 2'13" | 2'39" | 2'51" |
| 最慢配速 | 172'00" | 364'00" | 31'46" |
| 平均步频 | 90 | 104 | **156.8** |
| 平均步幅 | 164 cm | 158 cm | **110 cm** |

两个方向性偏差：

1. **极端慢点深度不足**：真机能到 364 min/km（v=0.046），我们最低 31'46"（v=0.52）。
   差在 `track::MIN_SAMPLE_GAP_M = 0.5`——它把相邻采样点最小间距钉在 0.5m，
   5 秒内最多走 0.5m，于是配速上限被钳在 166 min/km，实际只到 31'46"。
2. **步态是「小步高频」，真机是「大步低频」**：步频差 67%、步幅差 33%，
   乘积相同所以配速对得上。若真机口径是计步器少计后的派生值，我们的
   `totalSteps` 会系统性偏高约 1.5 倍。

## 逐点报文（已复核）

原始样本在 `/sdcard/workspace/re/zjwh740/evidence/obs_real_20261002.json`
（114 点、27 字段，含真实坐标故不入库）。以下数字由该文件直接算出：

### `speed` 的逐点分布

| | 真机 | 当前实现（2km/720s） |
|---|---|---|
| 中位 | 4.65 | 5.07 |
| 均值 | **13.93** | 11.95 |
| 最小 | 2.68 | 2.65 |
| 最大 | **260.42** | 49.90 |
| `v<2 m/s` 占比 | **14.7%** | 28.5% |

两条结论：

1. **真机 `speed` 均值本来就是 13.93**，不是 4~5。均值被 5 个极端点
   （88.65 / 97.77 / 146.20 / 154.32 / 260.42）拉高，中位数只有 4.65。
   所以「配速图一片 10 分、平均配速却 5'30"」在**真机记录上同样成立**，
   这是 App 纵轴被极端点撑开后的观感，不是数据错误。
2. `speed × avgSpeed ∈ [15.63, 16.98]`，逐点恒等于 `1000/60`，而
   `speed × bdS ∈ [9.33, 90.93]` ——`bdS` 是独立的滤波量，**不与 `speed` 同源**。
   任何「让 speed 跟随 bdS」的改法都会破坏逐点恒等式，不要做。

### `avgSpeed` 就是位置差分（不要改成独立测速）

95 个可比点上，`avgSpeed` 与 `ΔtotalDis/Δt`：相关系数 **0.991**、残差
均值 −0.030 m/s、残差 sd 0.212、最大 |残差| 1.91。所以设备端报的速度就是
位置差分，我们的口径一致。

### `ΔtotalDis` 的真实分布

| | 真机（n=113） | 当前实现 |
|---|---|---|
| 均值 | 14.90 | 14.30 |
| 标准差 | **9.40** | 10.79 |
| 最大 | 31.07 | 37.86 |
| `>20m` | 36 | 47 |
| `<5m` | 28 | 44 |
| `==0` | **12** | 0 |

我们的分布**更散**（>20m 和 <5m 都偏多、没有真正的零点），真机则是
「多数落在中段 + 少数几乎不动」。
